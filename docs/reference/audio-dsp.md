# Action audio: design and verification

Player controls are on [Options page 2](modes.md#action-card-audio-effects). This note distinguishes measured DSP behavior from live listening, which still needs a desktop playtest.

## Signal path and safety

The existing capture/Koi-Koi envelope in `src/ui_board.c` still drives the effect. Its strength ramps up, can build across successive actions, and fades. The new sliders set the maximum amounts, not a permanent effect on all music. The page-2 **Test Effect** switch explicitly auditions that maximum: it routes a match track through this same callback with the action target held at 1 (ON) or released to 0 (OFF). OFF retains the same stream/position for dry comparison, not a second sample or a simulated filter. Leaving page 2 restores menu playback. No audition state is saved. Menu music has no attached processor. Ordinary card sound files are not replaced or routed into this processor.

The callback in `src/ui_audio.c` uses the existing fixed-size stereo comb/diffusion tank. Added processing is local to that callback:

1. **Bass:** an RBJ low shelf with a +10 dB low-frequency endpoint. A smoothly blended shelf gives the selected low-frequency gain, multiplied by the action envelope. Only the **added shelf component** passes through a stereo-linked compressor: maximum ratio **4:1**, threshold **0.35 linear peak**, nominal **5 ms attack / 120 ms release**. It is then summed with the untouched original music. This replaces the old 8:1 whole-track compressor, which could make music quieter. +10 dB remains the small-signal endpoint: already-loud bass gets a controlled boost, not an unsafe promise of 10 dB more output regardless of headroom.
2. **Reverb feed:** both bass-processed channels feed the existing stereo tank. Its output is split into Mid and Side. The reverb return is high-passed until the last **20%** of the reverb control, where a smoothstep opens the bass return; at maximum it includes the full-band return. Increasing the room setting also opens the return's high-frequency bandwidth and increases its wet mix. A dry centre remains present even at maximum.
3. **Width:** the original Side and a separate pair of **one-sample first-order all-pass phase filters** contribute to the width stage. The phase filters have transfer `H(z) = (a + z⁻¹)/(1 + a·z⁻¹)` with coefficients +0.65 and −0.65. There is **no reverb-tank or slapback feed into width**, no long delay buffer, and no delayed dry path. The short filter response is checked explicitly with impulses at all width settings; this is not a claim that a phase filter has zero group delay. Maximum width opens its low-frequency contribution too. It is **not pure Side conversion**: `L = M + S`, `R = M - S` retains the centre, so mono fold-down retains Mid. Added Side correlated with Mid is projected out using running power/cross-power estimates, reducing a sustained tone's tendency to lean into one ear. Added Side has an RMS budget; sources already wider than that budget do not get additional Side-energy allowance. This avoids worsening pre-existing anti-correlation, but cannot repair an MP3 whose original stereo mix already cancels in mono.
4. **Output protection:** the added-bass compressor is stereo-linked. A final soft-knee limiter uses one shared gain for both output channels, preserving their instantaneous ratio. It starts at **0.88** and bounds active output below **0.98** full scale. The old whole-track bus compressor was removed. This leaves more headroom for boosted bass without sustained whole-track ducking; near-full-scale input can still require peak limiting. With no action, or all controls at zero after their ramps settle, the input is left bit-identical, including hot samples and signed zero.

The UI publishes all three controls as one lock-free atomic integer snapshot (C99 GCC/Clang builtins); the audio thread owns the filters, smoothing, and delay lines. Track-transition resets are requested atomically and performed on the audio thread. There is no allocation, file access, new dependency, or UI-thread filter mutation in the callback. Existing BGM/SFX volume controls and the action trigger logic are unchanged.

### Device-rate limitation, explicitly checked

Raylib 5.5 invokes stream processors **after** conversion to the output device's float-stereo format, before volume/mixing. The MP3's `Music.stream.sampleRate` is therefore **not** the processor's sample rate. Raylib's public API does not expose the device rate. We do not incorrectly substitute the source file rate.

To avoid changing or rebuilding the game's Raylib dependency, this change retains the engine's sample-domain delay lengths and nominal **44.1 kHz** tuning. The bass shelf midpoint is nominally **140 Hz** and return high-pass nominally **300 Hz**; actual cutoffs scale with device rate, and actual delay/attack/release times scale inversely. The tests exercise **44.1, 48, and 96 kHz** device-frame sequences. Their bass endpoint, linked channel gain, numerical safety and mono compatibility pass at all three rates. This is **not** a claim of identical frequency curves or reverb time on every device. Exact rate-invariant timing would require exposing/configuring the Raylib device rate in a separate dependency change.

## Checks run (22 October 2026)

`./tests/test_audio_dsp.sh` runs the previous presence-band/SFX checks **without weakening their thresholds**, followed by `tests/test_action_audio.c`, which processes actual sample arrays through the real callback:

- Exact bypass with hot stereo input, and exact bypass again after the action fades.
- At maximum width on mono noise: L/R balance within **0.02 dB**, correlation about **+0.344**, and preserved mono centre. Mono 40 Hz, 1 kHz and 8 kHz tones stay within **0.3 dB** of equal L/R RMS at all three tested rates; their mono fold-down error is below **2 × 10⁻⁷**.
- Quiet 20 Hz bass at maximum: **+9.995 to +10.000 dB**; midpoint setting: approximately **+4.98 to +5.00 dB**. At 8 kHz the bass-only gain is effectively zero. A loud 20 Hz tone (0.8 input amplitude) now gains **+2.87 to +2.89 dB**, rather than the old approximately −7 dB. A high-frequency tone immediately after a loud kick stays within **0.004 dB** of its original level, checking that the bass compressor no longer holds down the rest of the music. Channel-ratio tests verify linked rather than independent-ear compression.
- Width-only impulse tail after 5 ms is below **7.2 × 10⁻⁸** across width settings 25/50/75/100% and all three rates. The new regression fails against the old implementation (about **0.005** delayed output), proving it catches the reported echo rather than just testing stereo energy. Reverb retains its intentional long tail.
- A 40 Hz burst's reverb tail at 100% is **33–46 dB** stronger than at 80%, checking that bass is admitted late rather than simply making everything louder.
- Already-wide synthetic source: correlation **−0.387 → −0.387**, rather than adding further anti-correlated energy.
- Finite/bounded output under full-scale noise, smoothed slider steps, variable callback chunk sizes, transition resets, and invalid-control handling. AddressSanitizer and UndefinedBehaviorSanitizer also pass.
- The old presence-band regression now measures approximately **−3.3 dB Side/Mid**, passing its unchanged **−12.5 dB** minimum. Previously it failed at −18.7 dB with the unequal-ear decode.

Additional offline checks decoded the first **30 seconds each** of the shipped `game1.mp3` and `game3.mp3` with Raylib's bundled `dr_mp3`, and ran width-only, bass-only and all-maximum settings through the callback. Both decoded as 44.1 kHz stereo. Output stayed finite and below 0.98 full scale. For bass-only processing, identical-window overall RMS gains were **+0.058 dB** (game1) and **+5.902 dB** (game3), with no overall level reduction. Low-frequency RMS gains, measured using four cascaded 140 Hz one-pole low-passes, were **+5.422 dB** and **+6.425 dB** respectively. The filtered-band measurement isolates bass; it is not an integrated/perceptual loudness or LUFS measurement. Low-level width-only mono-null error stayed below **10⁻⁹**. `game1.mp3` already had negative correlation (**−0.218**); width-only kept it at **−0.218**, rather than making it more negative. These are offline numerical measurements, **not a claim of listening on speakers or headphones**.

Audition tests additionally check ON/OFF target values, actual wet sample changes versus exact dry samples after release, no track restart on a toggle, end-of-track advance, unavailable-music fallback, and automatic exit on page navigation/Back. Pagination, slider bounds, modal click blocking, save/load and bad settings are covered by `./tests/test_music_folder.sh`. Live layout, perceived strength on different music/headphones, and complete Windows/web builds remain to verify.

## Online source material reviewed

- [Raylib 5.5 audio implementation](https://github.com/raysan5/raylib/blob/5.5/src/raudio.c): `ReadAudioBufferFramesInMixingFormat()` and `OnSendAudioDataToDevice()` establish the callback format/rate and its position before mixing.
- [Robert Bristow-Johnson's Audio EQ Cookbook, maintained by WebAudio](https://github.com/WebAudio/Audio-EQ-Cookbook/blob/main/Audio-EQ-Cookbook.txt): normalized low-shelf biquad equations; the +10 dB shelf uses `S = 1`.
- [JUCE compressor reference](https://github.com/juce-framework/JUCE/blob/master/modules/juce_dsp/widgets/juce_Compressor.cpp): reference for the conventional envelope/threshold/ratio gain law. This implementation uses a shared stereo peak detector rather than separate channel gains.
- [JUCE first-order IIR reference](https://github.com/juce-framework/JUCE/blob/master/modules/juce_dsp/processors/juce_IIRFilter.cpp): the normalized first-order all-pass transfer. Only standard filter maths is used; no JUCE implementation was copied.
- [JUCE reverb reference](https://github.com/juce-framework/JUCE/blob/master/modules/juce_audio_basics/utilities/juce_Reverb.h): reference for symmetric stereo wet mixing, smoothed parameters, and the distinction between sample-domain delay lengths and sample-rate-scaled delays.

These sources were consulted for behavior/math; no JUCE library or JUCE source was added to the game.
