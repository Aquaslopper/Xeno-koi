# Action audio: design and verification

Player controls are on [Options page 2](modes.md#action-card-audio-effects). This note distinguishes measured DSP behavior from live listening, which still needs a desktop playtest.

## Signal path and safety

The existing capture/Koi-Koi envelope in `src/ui_board.c` still drives the effect. Its strength ramps up, can build across successive actions, and fades. The new sliders set the maximum amounts, not a permanent effect on all music. The page-2 **Test Effect** switch explicitly auditions that maximum: it routes a match track through this same callback with the action target held at 1 (ON) or released to 0 (OFF). OFF retains the same stream/position for dry comparison, not a second sample or a simulated filter. Leaving page 2 restores menu playback. No audition state is saved. Menu music has no attached processor. Ordinary card sound files are not replaced or routed into this processor.

The callback in `src/ui_audio.c` uses the existing fixed-size stereo comb/diffusion tank. Added processing is local to that callback:

1. **Bass:** an RBJ low shelf with a +10 dB low-frequency endpoint. A smoothly blended shelf gives the selected low-frequency gain, multiplied by the action envelope. Only the **added shelf component** passes through a stereo-linked compressor: maximum ratio **4:1**, threshold **0.35 linear peak**, nominal **5 ms attack / 120 ms release**. It is then summed with the untouched original music. This replaces the old 8:1 whole-track compressor, which could make music quieter. +10 dB remains the small-signal endpoint: already-loud bass gets a controlled boost, not an unsafe promise of 10 dB more output regardless of headroom.
2. **Reverb feed:** both bass-processed channels feed the existing stereo tank. Its output is split into Mid and Side. The reverb return is high-passed until the last **20%** of the reverb control, where a smoothstep opens the bass return; at maximum it includes the full-band return. Increasing the room setting also opens the return's high-frequency bandwidth and increases its wet mix. A dry centre remains present even at maximum.
3. **Width:** widen the **existing** stereo difference, not a phase-shifted copy of the centre. With `M = (L+R)/2`, `S = (L-R)/2`, and `s = width * action`, the requested Side expansion is `s * (1.2 + 4.8*s*s)`. Before the safety guards, this scales existing dry and room Side by up to **7×** while retaining Mid. The source-aware running-power budget rises smoothly from 0.49 to **1.0** Side/Mid power at maximum; already-wide sources do not receive further Side-energy allowance. Correlated room return retains its covariance correction. This is a request subject to the guard/limiter, not a promise of seven times more output on every track. **Mono stays mono when Reverb is zero.** Original panning is expanded, not replaced with an invented left/right phase lead. The former Hilbert path had equal ear levels but a fixed quadrature polarity: swapping input channels did not swap the output. That was a real fixed-side flaw missed by RMS and correlation measurements, so the synthetic path has been removed, not just retuned. Both dry channels and bypass retain their previous **64-sample** timing alignment (**1.451 ms at 44.1 kHz**, 1.333 ms at 48 kHz, 0.667 ms at 96 kHz); the buffer now only holds that alignment. With Reverb zero, width adds no inter-ear delay or reverb/slapback contribution. The original centre remains in the mono sum, subject to shared peak limiting. The guard limits further anti-correlated energy but cannot repair an MP3 whose original mix already cancels in mono. Reverb can still create its intentional stereo ambience; Width expands its existing Side too.
4. **Output protection:** the added-bass compressor is stereo-linked. A final soft-knee limiter uses one shared gain for both output channels, preserving their instantaneous ratio. It starts at **0.88** and bounds active output below **0.98** full scale. The old whole-track bus compressor was removed. This leaves more headroom for boosted bass without sustained whole-track ducking; near-full-scale input can still require peak limiting. With no action, or all controls at zero after their ramps settle, the output is bit-identical to the input **after the fixed 64-sample alignment**, including hot samples and signed zero. Bypass is not zero-latency.

The UI publishes all three controls as one lock-free atomic integer snapshot (C99 GCC/Clang builtins); the audio thread owns the filters, smoothing, and delay lines. Track-transition resets are requested atomically and performed on the audio thread. There is no allocation, file access, new dependency, or UI-thread filter mutation in the callback. Existing BGM/SFX volume controls and the action trigger logic are unchanged.

### Device-rate limitation, explicitly checked

Raylib 5.5 invokes stream processors **after** conversion to the output device's float-stereo format, before volume/mixing. The MP3's `Music.stream.sampleRate` is therefore **not** the processor's sample rate. Raylib's public API does not expose the device rate. We do not incorrectly substitute the source file rate.

To avoid changing or rebuilding the game's Raylib dependency, this change retains the engine's sample-domain delay lengths and nominal **44.1 kHz** tuning. The bass shelf midpoint is nominally **140 Hz** and return high-pass nominally **300 Hz**; actual cutoffs scale with device rate, and actual delay/attack/release times scale inversely. The tests exercise **44.1, 48, and 96 kHz** device-frame sequences. Their bass endpoint, linked channel gain, numerical safety and mono compatibility pass at all three rates. This is **not** a claim of identical frequency curves or reverb time on every device. Exact rate-invariant timing would require exposing/configuring the Raylib device rate in a separate dependency change.

## Checks run (22 October 2026)

`./tests/test_audio_dsp.sh` runs the previous presence-band/SFX checks **without weakening their thresholds**, followed by `tests/test_action_audio.c`, which processes actual sample arrays through the real callback:

- Bit-identical bypass after 64 samples of alignment, including hot stereo input and again after the action fades. Chunked callback tests verify that this alignment stays constant across ON/OFF.
- **Channel-exchange regression:** processing a stereo fixture after swapping L/R must equal the original output with L/R swapped. Tested at 25/50/100% width, with bass off/on and hot peaks, at all three frame rates, with Reverb zero to isolate width/bass. The previous implementation fails immediately (maximum sample error **0.228065** at 25%); the replacement measures **zero** in every case, against a 2×10⁻⁷ bound. Equal ear RMS alone could not detect this defect.
- Mono noise at maximum width stays mono: correlation **1.000**, Side **zero**, both ears identical. Mono 40 Hz, 1 kHz and 8 kHz tones also have zero Side. Aligned mono fold-down error stays below **2×10⁻⁷**. These expectations deliberately replace the old requirement to synthesize stereo from mono.
- A centre-heavy, amplitude-modulated **stereo** harmonic fixture at 25/50/100% width reaches Side/Mid RMS **0.225 / 0.361 / 1.000** at all three rates. Each tested step must increase the ratio by at least 50%, and maximum must exceed 0.85. Its Side contains distinct source parts, not a quadrature copy of Mid; its aligned mono centre is checked sample by sample.
- Quiet 20 Hz bass at maximum: **+9.995 to +10.000 dB**; midpoint setting: approximately **+4.98 to +5.00 dB**. At 8 kHz the bass-only gain is effectively zero. A loud 20 Hz tone (0.8 input amplitude) now gains **+2.87 to +2.89 dB**, rather than the old approximately −7 dB. A high-frequency tone immediately after a loud kick stays within **0.006 dB** of its original level, checking that the bass compressor no longer holds down the rest of the music. Channel-ratio tests verify linked rather than independent-ear compression.
- **Per-frequency mono-balance regression:** six centred tones (100/300/1,000/3,000/8,000/15,000 Hz) play together. Every tone measures **0.0000 dB** L/R difference, both in the first aligned 100 ms and after settling, at 25/50/100% width and all three rates; the test now requires <10⁻⁶ dB rather than tolerating FIR onset bias. These checks complement, not replace, the channel-exchange test on actual stereo input.
- Width-only impulse output after 5 ms is **zero** at width settings 25/50/75/100% and all three rates. There is no reverb/slapback contribution. Reverb retains its intentional long tail.
- A 40 Hz burst's reverb tail at 100% is **33–46 dB** stronger than at 80%, checking that bass is admitted late rather than simply making everything louder.
- Already-wide synthetic source: correlation **−0.387 → −0.387**, rather than adding further anti-correlated energy.
- Finite/bounded output under full-scale noise, smoothed slider steps, variable callback chunk sizes, transition resets, and invalid-control handling. AddressSanitizer and UndefinedBehaviorSanitizer also pass.
- The old presence-band regression now measures approximately **−0.9 dB Side/Mid**, passing its unchanged **−12.5 dB** minimum. Previously it failed at −18.7 dB with the unequal-ear decode.

Additional offline checks decoded the first **30 seconds each** of the shipped `game1.mp3` and `game3.mp3` with Raylib's bundled `dr_mp3`, and ran width-only, bass-only and all-maximum settings through the callback. Both decoded as 44.1 kHz stereo. Output stayed finite and below 0.98 full scale. For bass-only processing, identical-window overall RMS gains were **+0.058 dB** (game1) and **+5.902 dB** (game3), with no overall level reduction. Low-frequency RMS gains, measured using four cascaded 140 Hz one-pole low-passes, were **+5.422 dB** and **+6.425 dB** respectively. The filtered-band measurement isolates bass; it is not an integrated/perceptual loudness or LUFS measurement. Low-level width-only mono-null error stayed below **10⁻⁹** after compensating for the 64-sample alignment. `game3.mp3`, the centre-heavy track, changes from source correlation **0.936** to **0.214** at maximum width, with width-only overall balance **−0.104 dB** (source −0.031 dB). This is about **39% Side energy**, versus 7% in the earlier conservative implementation, using its existing stereo content rather than artificial phase. `game1.mp3` already has negative correlation (**−0.218**); width-only stays close at **−0.223**, with no further Side-energy allowance once its running source power exceeds the budget. All-maximum peaks are **0.95877 / 0.97248** for game1/game3. Offline callback CPU cost was approximately **0.14–0.31 seconds per 30 seconds of audio** in this sandbox; this is not a hardware-wide performance guarantee. These are offline numerical measurements, **not a claim of listening on speakers or headphones**.

Audition tests additionally check ON/OFF target values, actual wet sample changes versus exact dry samples after release, no track restart on a toggle, end-of-track advance, unavailable-music fallback, and automatic exit on page navigation/Back. Pagination, slider bounds, modal click blocking, save/load and bad settings are covered by `./tests/test_music_folder.sh`. Live layout, perceived strength on different music/headphones, and complete Windows/web builds remain to verify.

## Online source material reviewed

- [Raylib 5.5 audio implementation](https://github.com/raysan5/raylib/blob/5.5/src/raudio.c): `ReadAudioBufferFramesInMixingFormat()` and `OnSendAudioDataToDevice()` establish the callback format/rate and its position before mixing.
- [Robert Bristow-Johnson's Audio EQ Cookbook, maintained by WebAudio](https://github.com/WebAudio/Audio-EQ-Cookbook/blob/main/Audio-EQ-Cookbook.txt): normalized low-shelf biquad equations; the +10 dB shelf uses `S = 1`.
- [JUCE compressor reference](https://github.com/juce-framework/JUCE/blob/master/modules/juce_dsp/widgets/juce_Compressor.cpp): reference for the conventional envelope/threshold/ratio gain law. This implementation uses a shared stereo peak detector rather than separate channel gains.
- [Airwindows MidSide reference](https://github.com/airwindows/airwindows/blob/master/plugins/WinVST/MidSide/MidSideProc.cpp): independently checked sum/difference encoding of existing L/R content. Our normalization and guarded decoding are local; no Airwindows implementation, dither, or dependency was added.
- [SciPy FIR design reference](https://github.com/scipy/scipy/blob/main/scipy/signal/_fir_filter_design.py): antisymmetric odd-tap Type III linear-phase filters and Hilbert-transform FIR classification. Reviewed for the now-removed synthetic path. Mathematical quadrature and balanced levels did not guarantee a natural stereo image or channel-exchange symmetry. SciPy is not a game or test dependency.
- [JUCE first-order IIR reference](https://github.com/juce-framework/JUCE/blob/master/modules/juce_dsp/processors/juce_IIRFilter.cpp): reviewed for the prior first-order all-pass stage. Separate all-pass responses do not guarantee quadrature against an undelayed dry centre, so that stage has now been replaced. No JUCE implementation was copied.
- [JUCE reverb reference](https://github.com/juce-framework/JUCE/blob/master/modules/juce_audio_basics/utilities/juce_Reverb.h): reference for symmetric stereo wet mixing, smoothed parameters, and the distinction between sample-domain delay lengths and sample-rate-scaled delays.

These sources were consulted for behavior/math; no JUCE library or JUCE source was added to the game.
