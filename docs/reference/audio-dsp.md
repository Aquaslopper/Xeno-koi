# Action audio: design and verification

Player controls are on [Options page 2](modes.md#action-card-audio-effects). This note distinguishes measured DSP behavior from live listening, which still needs a desktop playtest.

## Signal path and safety

The existing capture/Koi-Koi envelope in `src/ui_board.c` still drives the effect. Its strength ramps up, can build across successive actions, and fades. The new sliders set the maximum amounts, not a permanent effect on all music. The page-2 **Test Effect** switch explicitly auditions that maximum: it routes a match track through this same callback with the action target held at 1 (ON) or released to 0 (OFF). OFF retains the same stream/position for dry comparison, not a second sample or a simulated filter. Leaving page 2 restores menu playback. No audition state is saved. Menu music has no attached processor. Ordinary card sound files are not replaced or routed into this processor.

The callback in `src/ui_audio.c` uses fixed-size buffers for a room/hall tank and a separate chorus. Processing stays local to that callback:

1. **Bass:** an RBJ low shelf with a +10 dB low-frequency endpoint. A smoothly blended shelf gives the selected low-frequency gain, multiplied by the action envelope. Only the **added shelf component** passes through a stereo-linked compressor: maximum ratio **4:1**, threshold **0.35 linear peak**, nominal **5 ms attack / 120 ms release**. It is then summed with the untouched original music. This replaces the old 8:1 whole-track compressor, which could make music quieter. +10 dB remains the small-signal endpoint: already-loud bass gets a controlled boost, not an unsafe promise of 10 dB more output regardless of headroom.
2. **Space reverb:** a Schroeder/Moorer-style room/hall tank: **eight parallel damped combs and four serial true all-pass diffusers per channel**, replacing the former four-comb/two-diffuser/slapback design. Independently chosen delay tunings use bounded, linearly interpolated taps. The room slider scales comb/diffuser delay lengths by **0.65–2.2×**, predelay by approximately **5–50 ms**, feedback by **0.55–0.93**, and diffuser coefficient by **0.50–0.65**. Raising it therefore expands reflection spacing and decay, not merely wet level. Dimensions follow the saved room control, not the capture envelope; repeatedly taking cards does not repeatedly sweep the delay lengths. Diffuser feedback remains below unity; comb state is bounded. Fixed low input gain reserves feedback headroom; reciprocal return staging restores the level without a signal-driven gain controller. The return retains its high-pass until the last **20%**, when low-frequency ambience opens in **Mid**. The Side return stays high-passed to keep deep room bass centred rather than letting a low-frequency tank resonance pull the whole track to one ear. Higher room values also open the return bandwidth and increase the wet mix. The existing input-driven ducking affects only the shared reverb-return gain, not panning or chorus gain. Room-size changes interpolate delay taps and may produce a glide while dragging; settled room settings have no room-size oscillator. This is algorithmic reverb, not convolution, shimmer, or a physical model promising exact dimensions in metres.
3. **Chorus, separate after the room:** two feed-forward fractional-delay voices, nominally **15 and 23 ms**, with up to **6 ms** delay modulation at nominal **0.60 Hz**. One voice uses sine and the other cosine. Each channel processes its own signal with the **same tap trajectories and fixed gains**; the LFO never pans the signal or changes channel gains. The parallel wet return rises to **100%** of the two-voice average while the direct signal is retained. Chorus intentionally has cyclic pitch/phase movement; it is not a claim of completely motionless sound. It adds no feedback tail. It also does not turn mono into artificial opposite-polarity stereo: identical inputs remain identical at the outputs with Reverb off. Mono fold-down equals applying the same chorus to the original mono fold-down (below peak limiting), but the chorus colours that mono signal; it is not an unchanged-original-mono claim. All stereo-width power meters, covariance correction, synthetic Side generation and the obsolete 64-sample alignment buffer have been removed. The processing order is **Bass → Space reverb → Chorus → linked peak limiter**.
4. **Output protection:** the added-bass compressor is stereo-linked. A final soft-knee limiter uses one shared gain for both output channels, preserving their instantaneous ratio. It starts at **0.88** and bounds active output below **0.98** full scale. The old whole-track bus compressor was removed. This leaves more headroom for boosted bass without sustained whole-track ducking; near-full-scale input can still require peak limiting. With no action, or all controls at zero after their ramps settle, the output is bit-identical to the input **with zero added latency**, including hot samples and signed zero.

The UI publishes all three controls as one lock-free atomic integer snapshot (C99 GCC/Clang builtins); the audio thread owns the filters, smoothing, and delay lines. Track-transition resets are requested atomically and performed on the audio thread. There is no allocation, file access, new dependency, or UI-thread filter mutation in the callback. Existing BGM/SFX volume controls and the action trigger logic are unchanged.

### Device-rate limitation, explicitly checked

Raylib 5.5 invokes stream processors **after** conversion to the output device's float-stereo format, before volume/mixing. The MP3's `Music.stream.sampleRate` is therefore **not** the processor's sample rate. Raylib's public API does not expose the device rate. We do not incorrectly substitute the source file rate.

To avoid changing or rebuilding the game's Raylib dependency, this change retains the engine's sample-domain delay lengths and nominal **44.1 kHz** tuning. The bass shelf midpoint is nominally **140 Hz** and return high-pass nominally **300 Hz**; actual cutoffs scale with device rate, and actual delay/attack/release times scale inversely. The chorus LFO rate also scales with device rate (0.60/0.653/1.306 Hz at 44.1/48/96 kHz), rather than falsely treating the MP3 rate as the device rate. The tests exercise **44.1, 48, and 96 kHz** device-frame sequences. Their bass endpoint, linked channel gain, numerical safety and mono compatibility pass at all three rates. This is **not** a claim of identical frequency curves or reverb time on every device. Exact rate-invariant timing would require exposing/configuring the Raylib device rate in a separate dependency change.

## Checks run (22 October 2026)

`./tests/test_audio_dsp.sh` runs the previous presence-band/SFX checks **without weakening their thresholds**, followed by `tests/test_action_audio.c`, which processes actual sample arrays through the real callback:

- Bit-identical **zero-latency** bypass, including hot input and signed zero, after action release and with all controls off. Chunked callback tests retain sample-for-sample equivalence.
- **Chorus channel exchange:** swapping L/R input swaps output exactly at 25/50/100%, bass off/on and 44.1/48/96 kHz with Reverb off. Maximum measured error is zero against a 2×10⁻⁷ bound.
- **Chorus wet-level regression:** on quiet noise, the isolated processed-minus-dry layer must have RMS between 0.50 and 0.75 times the slider amount relative to the dry signal. Maximum measures **0.579–0.580**, versus about 0.20 in the previous quiet mix. This replaces accepting merely nonzero modulation as sufficient strength; it is a signal-level check, not a listening guarantee.
- **Chorus modulation without auto-pan:** at 25/50/75/100%, a fixed 4:1 L/R tone ratio remains 4:1 sample by sample, while its output waveform demonstrably changes with the LFO. Mono impulses remain identical in both ears. Delayed voices are nonzero, and there is **zero chorus output after 40 ms** for an impulse at each tested rate—no feedback or long slapback.
- **Actual room growth:** impulse tests require both first-reflection time and normalized decay duration to increase at 25/50/100%. Reverse-integrated wet impulse energy (excluding the dry impulse), extrapolated from −30 dB to T60, measures approximately **0.61 / 1.12 / 5.95 s at 44.1 kHz**, **0.56 / 1.03 / 5.46 s at 48 kHz**, and **0.28 / 0.52 / 2.73 s at 96 kHz**. These are measured broadband impulse estimates, not frequency-independent decay guarantees or live listening. First reflection grows from **16.21 to 49.89 ms** at 44.1 kHz. Normalized late/early energy increases too, so simply turning wet gain up cannot pass this test.
- Quiet 20 Hz bass at maximum: **+9.995 to +10.000 dB**; midpoint setting: approximately **+4.98 to +5.00 dB**. At 8 kHz the bass-only gain is effectively zero. A loud 20 Hz tone (0.8 input amplitude) now gains **+2.87 to +2.89 dB**, rather than the old approximately −7 dB. A high-frequency tone immediately after a loud kick stays within **0.006 dB** of its original level, checking that the bass compressor no longer holds down the rest of the music. Channel-ratio tests verify linked rather than independent-ear compression.
- Loud boosted-bass/full-room feedback states stay below the internal safety clamp, guarding against distortion inside the tail. Instrumented offline processing of both shipped MP3 excerpts confirmed zero internal tank-clamp events in the tested modes.
- Full-room 40 Hz mono L/R balance stays within **0.35 dB** at the three tested rates, guarding against deep reverb bass pulling the image.
- A 40 Hz burst's tail at 100% room is **38.5–49.8 dB** stronger than at 80%, checking late admission of bass. The bass is present in the full-band centre of the room return, not exaggerated in opposite-polarity Side.
- Finite/bounded output under full-scale noise, smoothed slider steps, variable callback chunk sizes, transition resets, and invalid-control handling. AddressSanitizer and UndefinedBehaviorSanitizer also pass.
- The old presence-band regression now measures approximately **−11.1 dB Side/Mid**, passing its unchanged **−12.5 dB** minimum. Previously it failed at −18.7 dB with the unequal-ear decode.

Additional offline checks decoded the first **30 seconds each** of shipped `game1.mp3` and `game3.mp3` with Raylib's bundled `dr_mp3`, and ran chorus-only, bass-only and all-maximum settings through the callback. Both decoded as 44.1 kHz stereo. All output stayed finite and below 0.98 full scale. All-maximum peaks were **0.96687 / 0.97471**, with overall L/R balance **−0.370 / −0.180 dB**. Chorus-only balance was **−0.162 / −0.038 dB** (source −0.161 / −0.031 dB). Low-level chorus mono-fold commutation error was below **2×10⁻⁹**: folding the processed stereo matches processing the original mono fold-down, not the unchanged original waveform. Bass-only same-window overall RMS gains remain **+0.058 / +5.902 dB**, and four-pole 140 Hz filtered-band gains **+5.422 / +6.425 dB**. These are not LUFS measurements. Offline callback CPU cost was approximately **0.27–0.34 s per 30 s of audio** in this sandbox, not a hardware-wide guarantee. In additional level-matched quiet-input comparisons with Reverb/Bass off, the isolated maximum chorus layer rises from **−12.32 / −13.06 dB** below dry to **−2.96 / −2.60 dB** on game1/game3. The same input frames and no active limiter were used, and zero chorus produced zero difference. These are numerical checks, **not a claim of headphone/speaker listening**.

Audition tests additionally check ON/OFF target values, actual wet sample changes versus exact dry samples after release, no track restart on a toggle, end-of-track advance, unavailable-music fallback, and automatic exit on page navigation/Back. Pagination, slider bounds, modal click blocking, save/load and bad settings are covered by `./tests/test_music_folder.sh`. Live layout, perceived strength on different music/headphones, and complete Windows/web builds remain to verify.

## Online source material reviewed

- [Raylib 5.5 audio implementation](https://github.com/raysan5/raylib/blob/5.5/src/raudio.c): `ReadAudioBufferFramesInMixingFormat()` and `OnSendAudioDataToDevice()` establish the callback format/rate and its position before mixing.
- [Robert Bristow-Johnson's Audio EQ Cookbook, maintained by WebAudio](https://github.com/WebAudio/Audio-EQ-Cookbook/blob/main/Audio-EQ-Cookbook.txt): normalized low-shelf biquad equations; the +10 dB shelf uses `S = 1`.
- [JUCE compressor reference](https://github.com/juce-framework/JUCE/blob/master/modules/juce_dsp/widgets/juce_Compressor.cpp): reference for the conventional envelope/threshold/ratio gain law. This implementation uses a shared stereo peak detector rather than separate channel gains.
- [JUCE chorus implementation](https://github.com/juce-framework/JUCE/blob/master/modules/juce_dsp/widgets/juce_Chorus.h) and [parameter handling](https://github.com/juce-framework/JUCE/blob/master/modules/juce_dsp/widgets/juce_Chorus.cpp): reference for modulating interpolated short delays, rate/depth controls and wet mixing. Our two-voice feed-forward routing, parallel return and pan-preserving channel policy are local choices, not copied JUCE code.
- [JUCE reverb reference](https://github.com/juce-framework/JUCE/blob/master/modules/juce_audio_basics/utilities/juce_Reverb.h): reference for the classic eight-comb/four-diffuser topology, damping/feedback and sample-rate-scaled timing. Our tunings, room-size delay scaling and true all-pass equations are independently implemented. No JUCE dependency was added.

These sources were consulted for behavior/math; no JUCE library or JUCE source was added to the game.
